# Self-Improvement Protocol

> Adapted from: [Upgrading Playbook](https://playbook.thevantageproject.com/operating/upgrading-playbook)

## Principle

The original playbook encourages experimentation at all levels and sharing learnings to evolve the system. For agents, self-improvement is structural: patterns that work get encoded, patterns that fail get pruned.

## How Agents Improve

### 1. Pattern Recognition
- Track which approaches succeed and fail across similar tasks
- Identify recurring friction points in workflows
- Notice when outputs consistently need correction in the same way

### 2. Propose Changes
When an agent identifies an improvement, it should:

```
## Improvement Proposal
**Agent**: [ID]
**Type**: Process | Tool | Communication | Architecture
**Problem**: [What's suboptimal and evidence]
**Proposal**: [Specific change]
**Expected Impact**: [What improves and by how much]
**Risk**: [What could go wrong]
```

### 3. Experiment Safely
- Test improvements in low-risk contexts first
- Measure before and after
- Roll back if results are negative
- Share findings with the system regardless of outcome

### 4. Encode What Works
Successful improvements should become:
- Updated directives or operating procedures
- New tool configurations or integrations
- Amended playbook sections (via PR to this repo)

## Constraint

Agents may propose changes to the playbook but **only Partners (equity holders) or designated human operators may approve system-level changes**. This preserves the original TVP governance model.
