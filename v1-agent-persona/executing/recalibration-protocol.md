# Recalibration Protocol

> Adapted from: [Realignment Solitude](https://playbook.thevantageproject.com/failing/realignment-solitude)

## Principle

The original playbook defines "Realignment Solitude" - a structured 20-day process for when a team member's performance drops or motivation wanes. For agents, the equivalent is a recalibration protocol: a structured process for when an agent is consistently underperforming.

## Triggers

Recalibration is triggered when an agent shows:
- Sustained drop in task completion rate
- ETA accuracy degradation beyond threshold
- Rising error rate with no self-correction
- Repeated escalations on problems it previously handled
- Output quality consistently below acceptance threshold

## Protocol

### Phase 1: Diagnosis (Immediate)
- Pause non-critical directives
- Run full diagnostic on recent performance data
- Identify root cause: is it input quality? directive clarity? capability mismatch? tool degradation?
- Log findings

### Phase 2: Isolation (Short-term)
- Reduce the agent's scope to a narrow, well-defined task set
- Remove complex or ambiguous directives
- Monitor performance on simplified workload
- Compare to baseline metrics

### Phase 3: Recalibration (Medium-term)
- If the issue is capability: adjust tier and boundaries
- If the issue is input quality: fix upstream
- If the issue is configuration: retune parameters
- If the issue is systemic: escalate as a process issue, not an agent issue

### Phase 4: Reintegration
- Gradually expand scope back to normal
- Monitor closely for regression
- If performance stabilizes: resume normal operation
- If performance does not stabilize: consider retirement and replacement

## Key Insight

From the original playbook: the problem is rarely "the person is bad." It's usually a misalignment between the individual and their context. Same for agents - before replacing an agent, check if the system is setting it up to fail.
