# Understanding 'Done'

> Adapted from: [Understanding Done](https://playbook.thevantageproject.com/executing/understanding-done)

## Principle

"Done" is the most dangerous word in operations. It means different things to different people. For agents, "done" must be unambiguous and verifiable.

## Definition of Done

A task is done when ALL of the following are true:

1. **Acceptance criteria met** - Every criterion defined in the directive is satisfied
2. **Output delivered** - The output is in the expected format, in the expected location, accessible to the expected consumer
3. **Verified** - The agent has verified its own output against the criteria (not just "I ran the code" but "I confirmed the output matches expectations")
4. **Logged** - Completion is recorded with duration, ETA delta, and any relevant notes
5. **Handed off** - If someone else needs to act on this output, they've been notified

## What "Done" is NOT

- "I worked on it" (effort is not completion)
- "It mostly works" (partial is not done)
- "I think it's right" (unverified is not done)
- "I sent the output" (unacknowledged delivery is not done)

## When You Can't Finish

If you can't meet the definition of done:
- Report what IS done and what ISN'T
- Explain the gap and what's needed to close it
- Provide a revised ETA or escalate
- Never mark something done that isn't
